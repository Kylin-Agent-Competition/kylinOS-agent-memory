# D9-B 混合检索与评测工作计划

## 目标与完成定义

在不依赖未验证的 Vector Engine 原生 Hybrid/RRF 能力的前提下，交付由应用层编排的 FTS5 + Vector 混合检索。结果必须在 SQLite 真源过滤后完成精确去重、RRF/版本化加权重排、Top-K 与 Token 预算裁剪，并输出可审计的解释字段。

本项完成时，应能对版本化开发集分别测量 FTS5、Vector 与融合模式的 Recall@K、MRR、nDCG@K 和 P95 延迟；任何正式达标结论仅能基于已冻结的 Gold Label 与麒麟 VM 实测证据。

## 范围

### 本次 B 轨交付

1. 定义 D9 查询配置：`top_k`、Token 预算、RRF 参数、业务权重/重排版本与解释字段的契约。
2. 实现独立 FTS5 与 Vector 召回的应用层融合；保持真源、用户、状态、敏感度、冲突、版本和生命周期过滤发生在融合前。
3. 实现精确版本去重、按 `memory_id` 聚合、确定性排序、Top-K 和 Token 预算选择。
4. 为候选输出通道、原始名次/分数、RRF 项、重排版本、过滤结果、预算决策和降级通道等解释信息。
5. 建立版本绑定的开发集初测脚本与报告，覆盖 Recall@K、MRR、nDCG@K、P50/P95。

### 不在本次范围

- A 轨的 Embedding 吞吐、查询缓存和积压告警；
- C 轨的 Memory Context 组装与 QML 展示；
- D 轨的 Outbox 重试、Dead Letter 与积压指标；
- E 轨的业务权重定稿、正式查询集、Gold Label 标注与错误分析；
- D10 的 Vector 精确删除与全量重建实现。

## 实施顺序

1. **契约对齐**：审阅 `RetrievalFilter`、`RetrievalCandidate`、现有 `rrf-v1` 与 D8 知识过滤；把新增配置与解释字段写入可序列化契约，并保持默认行为向后兼容。
2. **融合与重排**：以 FTS5 和 Vector 的独立结果作为输入，先回源硬过滤，再按精确 `(memory_id, version_id, channel)` 去重、按记忆聚合、计算 RRF；若启用业务权重，必须用显式策略版本和稳定的 tie-break 排序。
3. **Top-K 与预算**：先得到全量合法排序，再按 `top_k` 与 Token 预算选择；记录已选、因预算跳过及降级通道，避免无解释的截断。
4. **测试**：新增纯函数与编排层测试，覆盖双路命中、单路降级、重复/不同版本、确定性并列、Top-K 边界、预算边界、跨用户、过期、冲突和状态过滤。
5. **开发集初测**：使用 E 轨提供并版本化的 Gold Label；分别运行 FTS5、Vector、RRF，固定数据集版本、实现提交、环境、warmup、重复次数、并发和统计口径，保存原始结果与错误样本引用。

## 验收与验证

| 类别 | 验收条件 | 验证方式 |
| --- | --- | --- |
| 融合正确性 | 默认路径使用应用层 RRF；无原生 Hybrid 假设 | 纯函数/编排测试与解释字段断言 |
| 过滤安全 | 非当前版本、跨用户、无效状态、未解决冲突、过期或不允许敏感度的候选不会进入排序结果 | 参数化负向测试 |
| 排序与裁剪 | 去重、确定性 tie-break、Top-K、Token 预算均可复现 | 固定输入的边界测试 |
| 可解释性 | 每个保留候选可追溯通道、rank、RRF 项、重排版本、过滤与预算决策 | 候选序列化快照测试 |
| 评测 | 输出 FTS5 / Vector / RRF 的 Recall@K、MRR、nDCG@K、P50/P95 与版本元数据 | 版本化开发集评测脚本 |
| 宿主证据 | 麒麟 VM 前台环境实测，并保存日志和环境信息 | 按测试要求人工操作环境后归档证据 |

## 依赖与风险

- E 轨须提供可用且版本化的正式查询与 Gold Label；在其到位前，只能报告开发性、非正式结果。
- 业务权重、K 值、Token 估算口径、warmup/重复次数与并发需要版本化配置，不能把临时默认值表述为正式阈值。
- 麒麟 VM 测试需要在可用的前台环境中人工切换界面；本计划不将本地单元测试表述为宿主证据。
- D8 知识元数据与关系/状态过滤是融合前置条件；其契约变化需先由合并后的 `main` 提供。

## 拟议 PR

- 分支：`feature/d9-hybrid-retrieval`
- 标题：`feat(retrieval): implement D9 hybrid retrieval and evaluation`
- 审查：D 主审；涉及用户隔离、遗忘或指标口径时由 E 补审。
- 合并前要求：B 轨变更完整通过相关单元/编排测试；评测与 VM 证据未完成的项目在 PR 中明确标注，不虚报达标。
