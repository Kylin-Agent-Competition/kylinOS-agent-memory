# 第一部分 ADR-015：forget_plan / forget_audit 表 + outbox priority（FRZ-DB-001 扩展）

## 一、背景

1. **D10-D（台账 R55）**：精准遗忘持久化层（表 + 迁移 + Repository + 事务/令牌语义）。FRZ-DB-001 冻结 5 张核心表 + D7D（memory_items/versions/receipts）+ D6-D（source_events）+ D10-B（vector 账本）扩展，**无遗忘计划/审计表**。
2. **契约 v0.3 已冻结**：`forget_plan` / `forget_audit` 两表 DDL 草案（§四.1/§四.2）、状态机 `pending → previewing → awaiting_confirmation → executing → completed / failed / rolled_back`（§三.3）、selector 明文生命周期（§四.8，HIGH-01）、`executed_count` 归属与「漏删不得报 completed」（§三.1/§三.2，MEDIUM-03）、`delete_mode` 门禁（§四.9，MEDIUM-04）。
3. **Outbox 无优先级**（`[02 §11.3]`）：`outbox` 无 priority 列，worker 按 `next_retry_at` 排序（`idx_outbox_pending`）；`aggregate_type CHECK IN ('turn','memory')` 冻结。遗忘/撤回任务必须优先于普通索引任务。

## 二、候选方案

### 2.1 forget 两表承载方式

| 方案 | 描述 | 评价 |
|---|---|---|
| **A（推荐）** | 新增 `forget_plan` + `forget_audit` 两表（契约 §四.1/§四.2 DDL），`db/schema.py` 单一真相，迁移 `20260901_add_forget_plan.py` | 契约冻结口径；与 ADR-013/014 扩展先例一致；计划持久化与最小审计分离，审计零正文 |
| B | 仅 `forget_plan`，审计并入 memory_entries | 审计混入业务记忆正文表，污染 FTS/检索；违背「最小审计零正文」 |
| C | 仅 outbox 承载计划/审计 | outbox 是待消费队列，消费/清理后不可回溯，审计失效 |

### 2.2 outbox 优先级实现（契约 §六）

| 方案 | 描述 | 评价 |
|---|---|---|
| **A（推荐，契约 F-4）** | 新增 nullable `priority` 列（INTEGER，默认 0；删除类事件 = 1）+ `idx_outbox_priority` 部分索引；worker `ORDER BY priority DESC, next_retry_at ASC`；`aggregate_type` CHECK 值域扩展 `'forget'` | 只增不改既有列；语义简单可测试；CHECK 值域扩展走本 ADR 变更控制 |
| B | 复用 `event_type='forget.executed'` 判断优先级（不新增列） | 无 DDL 变更，但 event_type 语义混合、排序条件复杂、索引失效 |
| C | 独立 forget 队列（新表） | 违背「SQLite Outbox + asyncio Worker，不引入额外消息队列」技术栈红线（`[02 §2.1]`） |

## 三、决策（草案推荐）

- **ADR-015 方案 A**：新增 `forget_plan` / `forget_audit` 两表 + outbox `priority` 列 + 部分索引 + `aggregate_type` CHECK 值域扩展；迁移 `20260901_add_forget_plan.py`（down_revision 以真实 Alembic head 为准，见「迁移」）；`db/schema.py` 同步为单一真相；既有表/索引/触发器/FTS5 **只增不改**。
- **决策状态**：DRAFT。以下 DDL 为契约 §四.1/§四.2 的 ADR 定稿版（补齐 `forget_audit` 的 `forget_mode / target_type / status` SQL CHECK——契约 Review #99 非阻断 2「留待 ADR-015 Schema 定稿补充」）。

## 四、DDL 定义（草案）

### 4.1 `forget_plan`（契约 §四.1）

```sql
CREATE TABLE forget_plan (
    id                    INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id               TEXT    NOT NULL,          -- 隔离键，禁止模型生成
    forget_plan_id        TEXT    NOT NULL,          -- 计划唯一 ID（宿主生成）
    forget_mode           TEXT    NOT NULL,          -- 五值枚举（v0.2 冻结）
    target_selector       TEXT,                      -- 明文生命周期（§四.8）：Preview 后/Hard Delete 完成前清除或置安全占位，可空
    target_type           TEXT    NOT NULL,          -- 四值枚举
    target_id             TEXT,                      -- 模式条件字段（互斥，SEC-FORGET-03）
    target_session_id     TEXT,
    target_topic          TEXT,                      -- 可能承载自然语言正文，按 §四.8 明文生命周期处理
    target_time_range     TEXT,
    resolved_target_ids   TEXT,                      -- JSON 数组（preview 产物，禁止模型生成；含 cascade 扩展目标）
    selection_hash        TEXT,                      -- Preview/Selection 稳定 Hash（确认凭据绑定 + 审计引用，非正文；长期持久化真源之一）
    status                TEXT    NOT NULL,          -- v0.2 冻结状态机（§三.3）
    requires_confirmation INTEGER NOT NULL DEFAULT 1, -- 禁止模型生成
    is_cascade            INTEGER NOT NULL DEFAULT 0, -- v0.2 冻结：默认 false
    delete_mode           TEXT    NOT NULL DEFAULT 'soft', -- soft / hard（v0.3/MEDIUM-04 可信来源门禁见 ADR-019）
    has_vector_cleanup    INTEGER NOT NULL DEFAULT 0, -- DEFERRED（待 B，本版不实现清理）
    confirmation_token    TEXT,                      -- 确认凭据 SHA-256 哈希（§五；明文不落库；消费后置 NULL）
    token_expires_at      TEXT,                      -- 凭据 TTL（默认 5 分钟，可调）
    affected_count        INTEGER,                   -- Preview 时确定并经确认的目标数量 = len(resolved_target_ids)，禁止模型生成（v0.3/MEDIUM-03）
    executed_count        INTEGER,                   -- 实际执行成功数量（v0.3/MEDIUM-03）；与 affected_count 不一致不得进入 completed
    executed_at           TEXT,                      -- 遗忘动作实际执行时间
    rollback_plan_id      TEXT,
    created_at            TEXT    NOT NULL,
    updated_at            TEXT    NOT NULL,
    CHECK (forget_mode IN ('single_item','session','topic','time_window','full_reset')),
    CHECK (target_type IN ('knowledge','preference','event','all')),
    CHECK (status IN ('pending','previewing','awaiting_confirmation','executing','completed','failed','rolled_back')),
    CHECK (delete_mode IN ('soft','hard'))
);
```

**索引**：

| 索引 | 定义 | 用途 |
|---|---|---|
| `uq_forget_plan_user_plan` | **UNIQUE(user_id, forget_plan_id)** | 计划级唯一 + 跨用户隔离双重限制（契约 §四.1） |
| `idx_forget_plan_user_created` | (user_id, created_at) | 时间线审计 |

### 4.2 `forget_audit`（契约 §四.2，最小审计零正文）

```sql
CREATE TABLE forget_audit (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    audit_id          TEXT    NOT NULL,              -- 审计唯一 ID
    forget_plan_id    TEXT    NOT NULL,
    user_id           TEXT    NOT NULL,
    forget_mode       TEXT    NOT NULL,              -- 五值
    target_type       TEXT,                          -- 四值（可空）
    delete_mode       TEXT    NOT NULL,              -- soft / hard
    is_cascade        INTEGER NOT NULL DEFAULT 0,
    affected_count    INTEGER,
    selection_hash    TEXT,                          -- Preview/Selection Hash（非正文）
    confirmation_ref  TEXT,                          -- 确认凭据的非敏感引用/Hash（不得保存原 Token）
    status            TEXT    NOT NULL,              -- 终态或动作后状态
    result_code       TEXT,                          -- 结果码（复用错误语义域，不新增）
    trace_id          TEXT,                          -- 追踪链（非正文）
    sensitivity_max   TEXT,                          -- 可选：结构化等级字段
    created_at        TEXT    NOT NULL,              -- 审计记录生成时间
    executed_at       TEXT,                          -- 遗忘动作实际执行时间（v0.3/MEDIUM-01 填写语义：Preview 阶段 NULL；execute 完成/失败/回滚终态必填）
    CHECK (forget_mode IN ('single_item','session','topic','time_window','full_reset')),
    CHECK (target_type IN ('knowledge','preference','event','all')),
    CHECK (status IN ('pending','previewing','awaiting_confirmation','executing','completed','failed','rolled_back')),
    CHECK (delete_mode IN ('soft','hard'))
);
```

**红线（契约 §四.2，验收见 §九）**：`forget_audit` 不保留正文（Memory 正文 / Summary / 原始 `target_selector` / 原始引用文本 / Preference·Knowledge 原值 / Confirmation Token 原文 / 敏感错误详情 / 可重新恢复被删正文的 Payload）；不只检查名为 `content` 的字段——`reason / details / source_reference / error_message` 等自由文本扩展字段均不得进入。

**索引**：`(user_id, created_at)` 时间线审计（与 `forget_plan` 同构；可在 ADR-015 签署定稿时确认是否需要，默认补充）。

### 4.3 `outbox` 变更（只增不改既有列 + CHECK 值域扩展）

```sql
ALTER TABLE outbox ADD COLUMN priority INTEGER DEFAULT 0;  -- DEFAULT 0（MEDIUM-03：历史行 NULL 与 0 语义统一为 0）；forget.* 事件 = 1
CREATE INDEX idx_outbox_priority ON outbox(priority, next_retry_at) WHERE priority = 1;  -- 部分索引
-- aggregate_type CHECK 值域扩展：'turn','memory' → 'turn','memory','forget'
-- SQLAlchemy schema 同步：Column('priority', Integer, server_default='0')（与 DDL DEFAULT 0 对齐）
```

**CHECK 值域扩展实现说明（D 决策记录 D1，已决策：采用方案 A）**：SQLite 不支持原地修改 CHECK 约束，扩展 `aggregate_type CHECK` 需**重建 outbox 表**（CREATE new → COPY → DROP old → RENAME，需在 `downgrade()` 对称回滚并保留既有数据）。既有冻结 `render_as_batch=False` 约束的是 **autogenerate 默认 batch**；本迁移为手写重建，仍须保证幂等与数据保留，或以显式 `op.batch_alter_table` 完成。~~备选（弱化）~~：不改 CHECK 的弱化方案（`forget.*` 以 `aggregate_type='memory'` 入队仅靠 priority 驱动）**已否决**（D1 决策：采用方案 A 扩展）。

**优先级取值域（契约 §六/§十二.3）**：`0`=普通索引任务（默认）；`1`=删除类（`forget.*`）；`2`=预留 urgent。文档化于本 ADR。

# 第二部分 ADR-019：forget.preview / forget.execute IPC 写方法（FRZ-IPC-007 扩展）

## 一、背景

1. **FRZ-IPC-007 冻结顶层方法路由**：活跃 `echo / health / memory.retrieve`；写方法 `turn.finalized`（ADR-010）、`event.ingest`（ADR-014）标 `CANDIDATE / BLOCKED_BY_HOST_MAPPING`；`memory.store` 保持 UNSUPPORTED_METHOD。**无遗忘方法**。
2. **`[02 §10.1]` 红线**：精准遗忘 preview 与 execute **分离**；execute 需确认令牌与幂等键；硬删除后审计不保留正文。契约 F-6：**必须两个方法**（`forget.preview` / `forget.execute`）。
3. **契约 §三/§五**：输入复用 E 轨 `ForgetPlan`（创建/Preview 前校验）；确认凭据（一次性、SHA-256 哈希存储、TTL 5 分钟、绑定 `user_id + forget_plan_id + selection_hash`）；`delete_mode` 可信决策来源由本 ADR 冻结（§四.9 / F-12，MEDIUM-04）。

## 二、候选方案

| 方案 | 描述 | 评价 |
|---|---|---|
| **A（推荐，契约 F-6）** | 两个写方法：`forget.preview`（解析生成 Preview + 凭据 + 落计划）、`forget.execute`（校验凭据 → 软删事务 → 审计） | preview/execute 分离是 `[02 §10.1]` 红线，必须两方法；语义清晰可独立测试 |
| B | 单方法 `forget` 内部分阶段 | 无法强制「确认后执行」边界，违背 preview/execute 分离红线 |
| C | execute 由 preview 响应内嵌执行 | 用户在确认前即被要求执行，无确认凭据流；否决 |

## 三、决策（草案推荐）

- **ADR-019 方案 A**：FRZ-IPC-007 路由表新增写方法 `forget.preview` / `forget.execute`；payload / 编排 / 幂等 / 错误语义按本草案冻结；production 默认**不注册** → `UNSUPPORTED_METHOD`，test/validation profile 显式注册（对齐 ADR-010/014 activation 方案 A+B）；激活状态标 **CANDIDATE / BLOCKED_BY_HOST_MAPPING**。
- **决策状态**：D 已决策（D1~D6 全部采用推荐方案），待 Reviewer E 签署后定稿。

## 四、IPC 契约定义（草案）

### 4.1 路由与激活

| method | 类型 | 激活状态 | 默认生产行为 |
|---|---|---|---|
| `forget.preview` | 写方法（落 `forget_plan` 行 + 凭据哈希） | `CANDIDATE / BLOCKED_BY_HOST_MAPPING` | 不注册 → `UNSUPPORTED_METHOD` |
| `forget.execute` | 写方法（软删 + 审计） | `CANDIDATE / BLOCKED_BY_HOST_MAPPING` | 不注册 → `UNSUPPORTED_METHOD` |

### 4.2 `forget.preview` 请求 payload（flat，`snake_case`，映射 E 轨 `ForgetPlan` 创建字段）

| JSON 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `forget_plan_id` | string | ✅ | 计划唯一 ID（宿主生成） |
| `user_id` | string | ✅ | **禁止模型生成**；与可信宿主注入比对（见「身份与安全」） |
| `forget_mode` | string | ✅ | 五值冻结：single_item / session / topic / time_window / full_reset；selector 互斥（SEC-FORGET-03，复用 `ForgetPlan` Domain 校验） |
| `target_selector` | string | ✅ | 用户输入选择器；**明文生命周期（HIGH-01）**：仅本次请求内用于解析，Preview 后服务端清除/置安全占位，不长期落明文 |
| `target_type` | string | ✅ | knowledge / preference / event / all |
| `target_id` / `target_session_id` / `target_topic` / `target_time_range` | string | 条件 | 模式条件字段（互斥，见 `forget_mode`） |
| `requires_confirmation` | bool | ✅ | **禁止模型生成**；宿主给定 |
| `is_cascade` | bool | 默认 | 默认 false（冻结）；true 仅业务 provenance 派生且目标全进 Preview |
| `delete_mode` | string | 默认 | **可信输入来源（本 ADR 冻结，MEDIUM-04）**：`soft` / `hard`，默认 `soft`；由可信宿主层显式给出，**Repository 不得按 `target_selector` 推导，LLM 不得终判**；`hard` 在跨轨 + L2 证据闭环前 Runtime fail-closed |
| `trace_id` | string | 可选 | 必须等于 IPC envelope.trace_id，不一致 → `INVALID_REQUEST` |

### 4.3 `forget.preview` 响应

| JSON 字段 | 说明 |
|---|---|
| `forget_plan_id` | 回显计划 ID |
| `status` | `awaiting_confirmation`（Preview 完成后） |
| `resolved_target_ids` | 系统规则引擎生成的 ID 快照（禁止模型生成；`[]` + `affected_count=0` 为合法零命中） |
| `affected_count` | = `len(resolved_target_ids)`（v0.3/MEDIUM-03） |
| `selection_hash` | Preview/Selection 稳定 Hash（凭据绑定 + 审计引用，非正文） |
| `confirmation_token` | **确认凭据明文（HIGH-02 冻结）**：随机 32B 一次性凭据，仅在 Preview 成功响应中回传一次；服务端只存 SHA-256 哈希（`forget_plan.confirmation_token`），明文不落库；调用方保存至 execute 使用 |
| `credential_ttl_seconds` | 凭据 TTL（默认 300） |
| `credential_ref` | 凭据的非敏感引用（Hash 前缀），供调用方自检；**不得作为 execute 凭据使用** |

> **确认凭据回传信道（HIGH-02 冻结，D4 已决策）**：凭据明文仅在 Preview 成功响应中以一次性明文回传一次（调用方保存至 execute），服务端只存 SHA-256 哈希（契约 §五/F-2）。`credential_ref` 仅为非敏感引用，不得作为 execute credential；不再提供独立确认信道方案。

### 4.4 `forget.execute` 请求 payload

| JSON 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `forget_plan_id` | string | ✅ | 计划 ID |
| `user_id` | string | ✅ | 与 Preview 一致；与可信宿主注入比对 |
| `confirmation_token` | string | ✅ | Preview 返回的确认凭据明文（服务端比对 SHA-256 哈希） |

`forget.execute` 的幂等键取自 FRZ-IPC-006 envelope 顶层 `idempotency_key`，该字段是唯一真源；payload 不定义也不携带 `idempotency_key`，避免双真源。

### 4.5 `forget.execute` 响应

| JSON 字段 | 说明 |
|---|---|
| `forget_plan_id` | 回显 |
| `status` | `completed` / `failed` / `rolled_back` |
| `affected_count` | 确认目标数量 |
| `executed_count` | 实际执行成功数量（v0.3/MEDIUM-03） |
| `executed_at` | 执行时间 |
| `audit_id` | 审计记录 ID |

### 4.6 状态机（契约 §三.3，冻结，本 ADR 映射）

```
pending → previewing → awaiting_confirmation → executing → completed / failed / rolled_back
```

- `previewing → awaiting_confirmation`：必须已形成完整 Preview（`resolved_target_ids + affected_count + selection_hash + user_id + forget_plan_id`）。
- `awaiting_confirmation → executing`：**D 轨接线前 fail-closed**；凭据校验失败 → `INVALID_REQUEST` 零副作用。
- 最终 Execute 只消费已确认的 `resolved_target_ids`；禁止模糊关键词直接删除 / 时间条件直接转大范围 SQL 删除 / Preview 后扩大目标集 / 模型生成补全最终 ID / 跨用户目标混入（契约 §三.3）。

### 4.7 确认凭据语义（契约 §五/F-2/F-3）

- 随机 32B 一次性凭据；**只存 SHA-256 哈希**（`forget_plan.confirmation_token`），明文不落库；审计仅存 `confirmation_ref`（非敏感引用/Hash，不得存原 Token）。
- 至少绑定：`user_id + forget_plan_id + selection_hash` + 有效期（默认 5 分钟，可调）+ 防重放。
- 必须拒绝：用户不匹配 / 计划 ID 不匹配 / Preview 已变化 / 目标快照不匹配 / 过期 / 重放（已消费）。
- 消费语义：execute 成功事务内将 `confirmation_token` 置 NULL（防重放）+ 写审计。

### 4.8 幂等（契约 §三.2/§五.3）

- 复用 FRZ-IPC-005 三元组 `(user_id, session_id, idempotency_key)` + `idempotency_cache`（TTL 24h，ADR-006），**不新建**遗忘专用幂等表。
- 复用 ADR-010/014 `request_fingerprint` 模式：同三元组 + 同指纹 → cache replay 返回首次结果；同三元组 + 不同指纹 → `IdempotencyConflictError` → `INVALID_REQUEST`。
- **隐私安全（对齐 ADR-014 v5 HIGH-01）**：`forget.preview` 请求携带 `target_selector`（可能含敏感正文）；`request_fingerprint` 对敏感内容取固定安全占位 `<SENSITIVE-OMITTED>`，**不得由敏感正文派生确定性 SHA-256** 落 `idempotency_cache`（防低熵离线枚举旁路）。`selection_hash` 由结构化 `resolved_target_ids`（业务对象 ID，非正文）派生，不作用于正文。

### 4.9 Handler 编排（固定顺序）

- `forget.preview`：payload 结构预检（含 `delete_mode` 值域与 `forget_mode` 互斥，复用 `ForgetPlan` Domain 校验）→ **trusted identity precheck（先于幂等查找，cache-bypass 防护，对齐 ADR-014 v5）** → 规则引擎解析（生成 `resolved_target_ids + affected_count + selection_hash`，真实结果；不支持模式 fail-closed）→ `UoW.execute_idempotent` 单事务（落 `forget_plan` 行 `pending→previewing→awaiting_confirmation` + 凭据哈希 + TTL + 清除 selector 明文 + response cache）→ 响应回传凭据明文一次。
- `forget.execute`：payload 结构预检 → trusted identity precheck → `UoW.execute_idempotent` 单事务（`business_fn`：凭据校验绑定/过期/消费 → 软删 `resolved_target_ids` → `executed_count` → 凭据置 NULL → 审计写入 → 状态 `executing → completed/failed/rolled_back`）。`executed_count != affected_count` 时**不得进入 completed**（漏删不得报完成）。

### 4.10 错误语义（复用冻结域，不新增错误码——契约 §八）

| 场景 | 行为 | 映射 |
|---|---|---|
| 确认凭据无效/过期/已消费/快照不匹配 | 拒绝执行，零副作用 | `INVALID_REQUEST`（safe_message 固定英文） |
| 幂等重放（同三元组 + 同指纹） | 返回首次结果 | 正常路径（cache 命中） |
| 幂等键复用但业务 payload 不同 | 拒绝 | `IdempotencyConflictError` → `INVALID_REQUEST` |
| 跨用户访问 forget_plan / 凭据 | 拒绝 | `INVALID_REQUEST`（Repository user 过滤 + UNIQUE(user_id, forget_plan_id)） |
| forget_mode 与 selector 不匹配 / 跨模式 selector | 拒绝 | `INVALID_REQUEST`（SEC-FORGET-03，Domain 校验） |
| 凭据与 Preview 快照不一致 | 拒绝执行 | `INVALID_REQUEST` |
| SQLITE_BUSY | `DatabaseLockedError` 降级 | FR-DB-003 既有语义 |
| 精准解析零命中 | 返回 `affected_count=0`（真实结果） | 正常路径，不假装删除 |
| 不支持的 Runtime（topic / time_window / full_reset / hard delete / cascade） | fail-closed | `INVALID_REQUEST`（固定 safe_message，不降级软删后报成功） |

## 五、身份与安全（对齐 ADR-014 v5 先例）

- test/validation profile：仅「声明内部自洽」身份一致性（payload 各身份字段一致 + 声明比对），如实标注自证，非宿主认证证据。
- production ACTIVE 硬门禁：独立 trusted host identity → 真实 fail-close 比对（`trusted_identity.user_id` vs payload.user_id），不一致 → `INVALID_REQUEST`，**先于幂等缓存查找**（cache-bypass 回归项）。
- 日志 sanitize_message；不记录 selector 明文/正文/PII；不出现任何密钥。
